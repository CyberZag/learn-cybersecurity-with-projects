# Choose the exercise that matches the role

This map connects role requirements to runnable practice. It is not a claim of completed work, employer affiliation or job eligibility. The exercises are original assistant-authored resources. Use the existing projects together instead of publishing a separate near-duplicate repository for every vacancy.

| Target role | Start here | Produce your own evidence |
|---|---|---|
| IAM / identity governance analyst | [Access review](ACCESS_REVIEW.md) | Role-to-permission comparison, leaver check, exception expiry review and documented decision rationale |
| SOC / security operations analyst | Existing [SOC authentication project](https://github.com/CyberZag/101-cybersecurity-analyst) plus IAM cases | Trace the events behind a finding, state alternative explanations and identify the next evidence needed |
| GRC / controls testing analyst | [Evidence-readiness exercise](SECURITY_CASEBOOK.md#grc--control-assurance-check-evidence-readiness) | Scoped control workpaper, evidence gaps and follow-up plan; no unearned compliance conclusion |
| Vendor cyber-risk analyst | Evidence-readiness exercise and IAM exception review | Fictional vendor evidence request, scope reconciliation and follow-up questions |
| Network operations / network administrator | [Ordered-rule exercise](SECURITY_CASEBOOK.md#network-administration-explain-an-access-path) | Flow matrix, rule-order diagnosis, limited change plan and regression test |
| Junior systems / cloud administrator | [Asset lifecycle](README.md), IAM and network cases | Joiner/mover/leaver checklist, approval evidence, configuration-change plan and rollback reasoning; no tenant deployment claimed |
| Junior penetration tester / application security | [Authorization reproduction](SECURITY_CASEBOOK.md#junior-pentesting--application-security-object-level-authorization) | Local reproduction, finding report, remediation and retest evidence |
| IT operations / infrastructure technician | Asset lifecycle and network cases | Inventory reconciliation, stale-request investigation and verified simulated change evidence |
| Technical support roles already prepared | [Support handoff](SUPPORT_PORTAL.md) | Clear unsent user update, next owner and evidence needed; do not call held cases resolved |

For each actual job, read the current description and choose a small relevant subset. Employer-specific application status, contact details, résumés and private records are tracked privately, not in this repository. Generated project plans and advisory résumé scores do not establish skills or guarantee interviews.

## Five-day practice plan around evening classes

1. **Day 1, 45 minutes before 6 p.m.:** reproduce one IAM case and explain a valid versus expired exception.
2. **Day 2, 45 minutes:** reproduce an authentication finding and write alternative explanations.
3. **Day 3, 45 minutes:** diagnose the network rule-order case and add one regression test.
4. **Day 4, 45 minutes:** complete a fictional control-evidence workpaper.
5. **Day 5, 45 minutes:** reproduce and retest the local authorization issue; practise a two-minute explanation of scope and limitations.

Dates and completion are intentionally blank. Record what you actually do, including failures and corrections, in the learner evidence template.

## Combined cybersecurity analyst practice

Use the [control-evidence workpapers](CONTROL_WORKPAPERS.md) with the access-review and asset-lifecycle cases for roles combining security operations, identity, inventory and governance. Practise gathering scoped evidence, documenting gaps, writing an unsent request, and retesting without inventing risk scores or audit conclusions. The generated examples are assistant work; record your own reproduction separately.
